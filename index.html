高级函数支持层级

BEHAVIOR 的高级函数位于 action primitive 层。上游大脑不能只输出自然语言，也不需要直接输出轮速或关节角；最合适的规划输出是 primitive 类型、目标对象实例，以及少量位姿参数。

Planner 推荐输出

primitive + object instance。例如 NAVIGATE_TO(table_obj)、GRASP(cup_obj)、PLACE_ON_TOP(table_obj)。对象必须是场景中的具体 object handle，不是文本类别。

通用调用形式

apply_ref(primitive, *args, attempts=5) 会生成逐步 robot action。另一个接口是离散 action：(action_idx, obj_idx)，其中 object 来自当前场景 addressable objects。

适配结论

Starter physical primitive 官方声明仍是 example / work-in-progress，目前只适配 Tiago 和 R1，并要求 HolonomicBaseJointController / JointControllers 为 absolute position mode。

Starter 高级函数 Planner 需要输入 内部承接内容 当前可用性 机器人适配
NAVIGATE_TO(obj) 目标对象实例，或对象列表。 采样目标附近 2D 位姿，检查可达性，调用 base motion planning，生成逐步 action。 物理执行 官方声明：Tiago、R1。其他机器人不应默认认为已适配。
_navigate_to_pose(pose_2d) (x, y, yaw)，可选 skip_obstacle_update。 将 2D pose 转成 base footprint pose，经 CuRobo 规划 base 轨迹并执行。 内部函数 适合二次封装为 planner 接口；官方高层 enum 中没有单独暴露该项。
_navigate_to_pose_direct(pose_2d) (x, y, yaw)，可选 low_precision。 不做完整轨迹规划，按当前位置差值生成 holonomic 或 differential base action。 内部函数 代码分支支持 HolonomicBaseJointController 与 DifferentialDriveController，但不等于官方全机器人 primitive 适配。
GRASP(obj) 待抓取对象实例。 必要时先导航到对象附近，采样 pregrasp / grasp pose，移动手，执行 sticky 或 assisted grasp。 物理执行 官方声明：Tiago、R1；要求机器人具备 manipulation 能力和合适 grasping mode。
PLACE_ON_TOP(obj) 目标承载对象实例；前提是手中已有物体。 按 OnTop predicate 采样放置位姿，必要时导航，移动手并释放物体。 物理执行 官方声明：Tiago、R1；要求目标对象支持 OnTop 放置关系。
PLACE_INSIDE(obj) 目标容器对象实例；前提是手中已有物体。 按 Inside predicate 采样放置位姿，必要时导航，移动手并释放物体。 物理执行 官方声明：Tiago、R1；要求目标对象支持 Inside 关系。
RELEASE() 无目标对象；依赖当前手中物体状态。 将手指移动到 upper limit，并检查 release 后手中不再持有对象。 物理执行 官方声明：Tiago、R1；要求 gripper controller 可用。
OPEN(obj) / CLOSE(obj) 可开合对象实例。 接口存在，但 Starter 源码中 _open_or_close 直接抛出 NotImplementedError。 不可作为稳定项 不建议作为当前物理执行能力汇报重点。
TOGGLE_ON(obj) / TOGGLE_OFF(obj) 可开关对象实例。 接口存在，但 Starter 源码中 _toggle 直接抛出 NotImplementedError。 不可作为稳定项 不建议作为当前物理执行能力汇报重点。
Symbolic 高级函数 Planner 需要输入 执行方式 测评含义
GRASP、PLACE_ON_TOP、PLACE_INSIDE、RELEASE 对象实例；place 类函数要求手中已有物体。 不执行完整低层物理，而是通过直接设置对象位置、抓取关系或后置状态完成。 高层逻辑验证 适合检验任务分解和对象关系，不代表真实动作执行。
OPEN、CLOSE、TOGGLE_ON、TOGGLE_OFF 具备 Open 或 ToggledOn state 的对象实例。 直接设置 object state，并检查后置条件。 高层逻辑验证 可用于状态规划测试，不应等同于物理开合/按键技能。
SOAK_UNDER、SOAK_INSIDE、WIPE 目标对象实例；通常要求手中已有可吸附或可清洁工具。 检查 ParticleSource / Contains / Covered / ParticleRemover 等 object states，并直接更新相关状态。 物质状态验证 适合评估任务前置条件与后置条件推理。
CUT、PLACE_NEAR_HEATING_ELEMENT、NAVIGATE_TO 切割目标、热源对象或导航目标对象实例。 切割通过 transition rule，热源放置通过采样 predicate 位姿，symbolic 导航直接设置机器人 pose。 高层方法验证 可验证 planner 是否选择正确工具和目标对象。
机器人类别 高级函数适配情况 对大脑测评的含义
Tiago、R1 官方声明适配 Starter physical primitives 当前明确只声明这两类机器人可用。 最适合作为“primitive 层大脑测评”的起点，尤其是导航、抓取、放置链路。
Fetch、Stretch、R1Pro 需验证 机器人具备移动操作硬件模型，但 Starter primitive 源码未声明全量适配。 可用于 controller 层或自定义 primitive 测试；不应直接承诺现成高层函数稳定可用。
Turtlebot、Locobot、Husky、Freight 非目标适配 navigation-only 机器人没有手臂/夹爪，不能运行抓取和放置 primitive。 适合点导航或底盘控制测评，不适合完整 object-level manipulation primitive 测评。
Franka、VX300S、A1、Franka Mounted 局部操作 具备操作结构，但无移动底盘；Starter 官方适配声明不包含这些机器人。 适合局部抓取/放置控制实验，不适合导航-操作一体的 primitive 测评。
BehaviorRobot 遥操作代理 官方定位为 VR teleoperation proxy。 不建议作为当前高级函数执行层测评主体。

家务 Task 支持

BEHAVIOR-1K Task Knowledgebase 当前列出 1016 个 Task。本页只保留能体现家务执行闭环的任务类型：导航取放、收纳、清洁、厨房处理、洗涤和庭院/泳池维护。

收纳 / 搬运 / 拆包

示例：unloading_groceries-0、unpacking_suitcase-0、unpacking_moving_van-0、unloading_shopping_items-0。常见 predicates 包括 ontop、inside、nextto。

烹饪 / 厨房处理

示例：baking_sugar_cookies-0、baking_cookies_for_the_PTA_bake_sale-0、wash_fruit_and_vegetables-0。可涉及 cooked、filled、inside、ontop 等 predicates。

清洁 / 洗涤

示例：vacuuming_floors-0、wash_a_backpack-0、wash_baby_bottles-0、treating_stains-0。Required Features 可包含 visual substance、physical substance、cloth。

地面 / 表面维护

示例：vacuuming_floors-0、waxing_floors-0、washing_windows-0。适合覆盖导航到目标区域、工具使用、表面覆盖状态变化。

泳池 / 热水浴缸

示例：adding_chemicals_to_hot_tub-0、adding_chemicals_to_pool-0、turning_on_the_hot_tub-0、turning_off_the_hot_tub-0。可涉及 contains、filled、toggled_on。

园艺 / 户外维护

示例：adding_chemicals_to_lawn-0、applying_pesticides-0、watering_outdoor_plants-0、watering_outdoor_flowers-0。常见场景包括住宅花园。
